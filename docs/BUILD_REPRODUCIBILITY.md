# Release rebuild reproducibility

Two consecutive `scripts/build.ps1 -Configuration release` builds were made from unchanged source on 2026-09-28. The preserved diagnostic manifest is `results/diagnostic/build-v3/20260928T075245Z-f24ff750/manifest.json`; the first attempted probe (`20260928T075227Z-890486ee`) failed before compiling because a child PowerShell process enforced its script execution policy. The successful probe used `-ExecutionPolicy Bypass` for this repository script only.

For both `helios.exe` and `helios_mpi.exe`, whole-file SHA-256 changed, while **every PE section had identical bytes**, including `.text`, `.rdata`, `.data`, and unwind sections. The same-length binaries differed at only two offsets: 136, the PE COFF timestamp field, and 216, the PE optional-header checksum field. The timestamp changed between builds; the checksum correspondingly changed. `byte_differences.json` records the exact offsets. The compiler/linker command and source bytes were unchanged. This supports identical emitted code and data for these two builds, but not bit-for-bit reproducible PE files. The benchmark manifest's executable hashes identify the exact binaries used. Neither source reproducibility nor execution semantics should be inferred solely from equality or inequality of whole-file hashes; validation still checks rendered pixels.
