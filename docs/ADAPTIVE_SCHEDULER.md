# Adaptive distributed scheduler

Helios divides each image into deterministic microtiles. MPI rank 0 coordinates one outstanding contiguous microtile batch per worker; it does not render in dynamic modes. Fixed dynamic assigns one microtile at a time. Static coordinator-only assigns each of two worker ranks one contiguous half. Rendering, seed, and pixel placement are identical across these scheduler modes.

The adaptive rule estimates each worker's pixels/second only after that worker returns an entire batch. It uses the returned batch's pixel count divided by the sum of tile render seconds, including synthetic stall when present. The first observation becomes the estimate; later observations use `0.5 × old + 0.5 × latest`. With default target 50 ms, initial batch 2, maximum 8, and `fair = max(1, floor(remaining/(2×workers)))`, the next batch is `min(remaining, floor(clamp(rate×0.050/tile_area,1,8)), fair, 8)`. The estimate is stale while a batch is in flight, and the policy does not know the cost of unrendered tiles. The diagnostic CLI can vary fixed batch, adaptive target, or initial size; formal V2 runs use the frozen defaults in [the candidate marker](FROZEN_EVALUATION_CANDIDATE.md).

The pre-change seven-block small-scene V2 data show that adaptive reduced assignment counts from 144 to median 30–50 but did not establish a consistent runtime advantage over fixed dynamic. On the synthetic two-times-slower-rank test, fixed dynamic also won. Dynamic redistribution itself gave the large gain over static on irregular scenes. The [policy audit](ADAPTIVE_POLICY_AUDIT.md) derives these statements from raw records and explains the separate medium diagnostics.

The medium diagnostic fixed-batch study found that large batches reduced assignment wait by milliseconds while increasing last-worker completion spread by several tenths of a second. At batch 8 on imbalanced medium, assignments fell from 144 to 18 and median worker wait from 0.012 to 0.002 s, but median wall time rose from 3.177 to 3.501 s and final-worker spread from 0.013 to 0.461 s. These measurements support a late-batch cost under the tested single-host conditions. A small adaptive target/initial-size sweep had no stable monotonic result; the algorithm and defaults were left unchanged before fresh formal evaluation.

Each dynamic run now records low-cost assignment counts, batch histogram, worker waits and effective throughput, MPI call occupancy, coordinator handling, and final completion times. Normal mode omits per-assignment trace objects. Diagnostic trace mode saves dispatch and receipt times, batch sizes, remaining work on receipt, and the rate estimate at dispatch. The 90%-completion tail is measured at whole-batch receipt boundaries, so coarse batches can jump directly from below 90% to 100% and make that value nearly zero. Use it alongside final-worker spread and trace, never alone. Blocking MPI-call time includes waiting for a peer and is not pure network time.
